# 从运行到自己修改

建议按下面的顺序阅读，每次改一处，记录改动前后的结果。

## 1. 一条样本是什么

打开 `artifacts/events.csv`，找一行：

```text
timestamp,user_id,video_id,watch_ratio,liked
```

这里每行代表一次真实发生在模拟器里的曝光。曝光后划走也是训练数据；完全没有曝光的视频没有标签。未曝光不等于不喜欢。

模型在推荐之前可用的是视频主题、时长和该用户过去的反馈。当前这条视频看了多久、是否点赞，都是事后标签。`training_examples` 中，`xs.append(...)` 在 `history.append(event)` 前面，顺序不能交换。你可以先预测一条样本，再改变它的当前标签，检查特征有没有变化。

`user_profile` 使用观看比例和点赞构造一个手写的兴趣状态。这个状态更新过程没有通过梯度学习。排序模型使用这些特征学习概率，两者可以分别修改。

## 2. 从公式读懂 Ranker.fit

每个样本有 9 个特征，`X` 的形状为 `(N, 9)`。两个任务的标签 `Y` 形状为 `(N, 2)`，参数 `W` 形状为 `(9, 2)`。

对一个任务：

$$z_i = x_i^T w,\qquad p_i = \sigma(z_i) = \frac{1}{1+e^{-z_i}}.$$

代码使用等价的 `0.5 * (1 + tanh(z / 2))` 避免指数溢出。损失为：

$$L(w) = -\frac{1}{N}\sum_i [y_i\log p_i + (1-y_i)\log(1-p_i)]
 + \frac{\lambda}{2}\sum_{j\ne 0}w_j^2.$$

梯度和更新为：

$$\nabla_w L = \frac{X^T(p-y)}{N}+\lambda\widetilde{w},\qquad
w\leftarrow w-\eta\nabla_w L.$$

`w[0]` 对应偏置，不施加 L2。两列分别应用同一个梯度公式，两个任务之间没有共享可学习参数；代码记录的 log loss 是两个任务 BCE 的平均，不包括 L2。`logaddexp(0, z) - y * z` 是同一个 BCE 的稳定算法。

打开 `artifacts/model.json`：`weights[1]` 是兴趣匹配对两项任务的权重，`weights[2]` 是时长权重。将兴趣匹配提高 1 时，对应任务的 log-odds 改变这个权重。概率的改变量还取决于原来的概率。

本模型将主题 one-hot 全部保留并加入偏置，存在冗余编码；L2 帮助约束权重。不要把单个主题系数当成因果效应。

## 3. 推荐一次发生了什么

`recall` 把未看过的目录缩小为最多约 80 个候选。`Ranker.predict` 对每个候选算两个概率。`recommend` 用固定的 0.7 / 0.3 权重组合它们，逐条选择，并减少后续同主题候选的分数；随机位置由探索填充。

候选池的随机渠道和最终列表的探索是两处不同的随机操作。候选池里随机入选的视频仍需竞争模型分数，最终探索位置则直接保留随机选择。

交互时加入一条反馈后，兴趣特征变了，固定模型就能给出不同分数。全局模型权重不会因此自动更新。想让全局模型继续训练，需要另外设计训练数据窗口、学习率和验证流程。

## 4. 五个可检查的练习

| 改动 | 如何检验 |
| --- | --- |
| 把 `user_profile` 改为始终返回均匀分布 | 保持时间划分与 seed 不变，重训后比较 AUC、log loss；保存一次改动记录 |
| 把兴趣衰减 `0.97` 改成 `0.8` 或 `1.0` | 在交互里连续给某主题正反馈，再开始划走；比较兴趣变化速度 |
| 修改 `recommend` 的组合权重 | 在 `evaluate` 中对同一目标计算多种分数；保持评估 relevance 固定，避免移动目标 |
| 把 `diversity_penalty` 设成 `0`、`0.12`、`0.3` | 固定历史和 seed，对比列表中的主题数及基础分均值；多样性增加未必提高预测收益 |
| 把 `exploration` 设成 `0`、`0.1`、`0.3` | 固定 k=10，检查探索标记数量；再改种子，比较推荐 ID 的覆盖范围 |

做完第一项，你应当能指出个性化来自哪个输入。做完第三项，你应当能区分学出来的模型参数和人指定的目标权重。先用不同 seed 验证观察是否稳定，再增加模型复杂度。

## 5. 用真实数据时会遇到什么

当前曝光由模拟器均匀随机选取，因此没有推荐策略主动挑样本产生的曝光偏差。真实日志通常已经受旧策略影响。只在旧策略曝光过的内容上算指标，不能直接断言新策略上线后的效果。这里也没有估计 propensity 或实现 IPS。

当前模拟器的偏好在一次实验中固定，视频只有已知主题与时长。即使交互能演示兴趣变化，也不能据此证明模型能处理真实的兴趣漂移、视频语义或长期满意度。

替换数据时，可以选带明确用户行为字段的公开推荐数据集，先检查使用条款和曝光语义。记录字段来源、时间单位、训练截止时间。当前代码假定所有视频从开始就可用，ID 是连续列表下标；接入真实目录时需要 ID 映射和发布时间过滤。

候选召回还需要单独评估：例如先定义时间截止点，在其后实际曝光且有正反馈的视频中，统计多少进入了模型召回集合；解释负例和未曝光项的来源，保留可复现的候选集合。不要将这里的 logged NDCG 当成全目录召回评估。
