# Minimal Short-video Recommender

用 Python + NumPy 学习短视频推荐：观看反馈 → 兴趣向量 → 多路召回 → 双目标排序 → 多样性与探索。

这是一个可在 CPU 上运行的教学项目，使用虚构视频元数据和模拟用户行为。只需 NumPy，无 API key、GPU 或外部数据下载。交互演示显示视频标题，不播放视频。

项目参考公开的推荐系统原理；代码、目标权重、阈值和数据分布均为本项目的教学设计，不能当作抖音内部算法或生产效果。

## 运行

需要 Python 3.10+。已在 Python 3.12.14、NumPy 2.3.5 上验证。

```bash
git clone https://github.com/WZatU/architect-journey.git
cd architect-journey/short-video-recommender
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python demo.py
```

从没有历史记录的用户开始，观察推荐如何随反馈变化：

```bash
python demo.py --interactive --user 999
```

输入 `w` 看完、`l` 看完并点赞、`s` 立即划走，也可以输入 `0.5` 表示看了一半。`q` 退出。每轮只反馈列表第一条，其余条目只是预览，不会被记成曝光。`--user 0` 则从模拟用户 0 的已有历史开始。

每次反馈后立即重算兴趣和推荐，全局排序模型的参数保持固定。每轮的随机探索种子不同。单个 10 条列表里有 1 个随机探索位置，因此交互中第一条也有机会来自探索。

## 算法

**兴趣向量。** 六个主题：AI、数学、钢琴、烹饪、篮球、旅行。每个主题从 0.5 份证据开始。历史反馈贡献 `0.97 ** age * (2 * watch_ratio - 1 + 1.5 * liked)`；`age` 是该用户历史中相隔的事件数。证据下限设为 0.05，再除以总和。因此看完与点赞增加对应主题的证据，划走减少证据，近期行为占比更高。

**召回。** 排除已经看过的视频，从兴趣、训练期完播率和随机渠道取候选，默认分别取 40、20、20 条，再去重。视频完播率采用 `(完播次数 + 1) / (曝光次数 + 2)` 平滑。候选并集可能少于 80 条。它是精确扫描目录的教学实现，没有近似向量检索。

**训练排序模型。** 输入为 9 维向量：偏置、用户对该视频主题的兴趣匹配、视频时长、6 维主题 one-hot。两组独立的逻辑回归权重分别预测：

```text
P(观看比例 >= 0.8 | 用户历史, 视频)
P(点赞 | 用户历史, 视频)
```

本项目把观看比例达到 80% 记为完播标签；这只是教学阈值。没有训练观看时长回归模型。模型权重由数据学习，兴趣更新规则和下面的组合权重由代码指定。

**输出顺序。** 基础分为 `0.7 * P(完播) + 0.3 * P(点赞)`。每选入一条同主题视频，该主题后续候选减去 0.12 分。默认将 `ceil(k * 0.1)` 个探索位置随机插入列表，从整个未看过的目录均匀抽取。`k=1` 时默认也会分配 1 个探索位置，实验单条纯排序时可设 `exploration=0`。返回值同时保留基础分和当时的调整分，便于检查排序。

## 默认实验

固定 `seed=42`，生成 120 个用户、600 条视频和 14,400 次均匀随机曝光。每个用户有 120 次不重复曝光，模拟器给用户分配隐藏偏好，再生成观看和点赞。隐藏偏好和隐藏视频质量没有交给模型。

按全局事件时间顺序分为训练 / 验证 / 测试 60% / 20% / 20%，分别为 8,640 / 2,880 / 2,880 行。每行特征只使用该用户此前的反馈；验证集选取训练轮次，测试标签不参与权重训练、轮次选择或热门统计。

验证和测试模拟连续使用场景：预测后才把该次反馈加入历史。因此后面的测试样本可以使用更早测试样本的已发生反馈，全局模型权重一直冻结。

`python demo.py --seed 42` 的一次实测如下，完整记录在 [`examples/metrics.json`](examples/metrics.json)。数值可能随数值库版本产生微小差异。

| 方法 | 完播 AUC | 点赞 AUC | logged NDCG@10 |
| --- | ---: | ---: | ---: |
| 全局平均概率 | 0.5000 | 0.5000 | 0.3526 |
| 按视频主题统计的概率 | 0.5213 | 0.5465 | 0.4014 |
| 个性化逻辑回归 | 0.7739 | 0.8632 | 0.7121 |

AUC 衡量正样本分数高于负样本的概率，随机或完全打平为 0.5。log loss 同时考察概率预测是否接近实际标签，越小越好。

这里的 NDCG 对每个用户**测试期已曝光的约 24 条视频**排序，使用 `relevance = 0.7 * complete + 0.3 * liked`、`gain = 2 ** relevance - 1`、对数位置折扣，再对全部用户取平均。没有正反馈的用户记 0。该指标只评估冻结排序模型，未评估召回、探索和多样性重排，也不能衡量从全部 600 条视频中找出好视频的能力。

模拟器特意产生了可以从主题行为推断的偏好。这些指标检验代码在该模拟任务上是否有效，不能外推到真实用户、真实视频或线上增长；尚无真实数据评估、A/B 实验或生产规模验证。

## 输出与测试

默认输出到 `artifacts/`，也可以通过 `--out` 指定目录：

| 输出 | 内容 |
| --- | --- |
| `videos.csv` | 虚构视频主题、时长和标题 |
| `events.csv` | 模拟曝光、观看比例、点赞与事件顺序 |
| `model.json` | 特征顺序、两组学习权重，可通过 `Ranker(payload["weights"])` 重建 |
| `metrics.json` | 数据划分、三个模型指标、训练曲线与最佳轮次 |
| `recommendations.json` | 初始推荐列表、预测概率、分数及探索标记 |
| `feedback-<UTC时间>.jsonl` | 每次交互运行的反馈，逐行保存 |

重新运行会重新生成实验并覆盖前五类文件；交互日志另存新文件，不会自动导入下次实验。不同交互日志属于独立运行，合并前需要统一事件顺序。CSV 中 `timestamp` 是严格递增的事件序号，不是实际时间。视频 ID 在当前实现中等于目录列表下标。

```bash
python -m unittest discover -s tests -v
```

测试覆盖当前标签与未来反馈不泄漏到历史特征、正负反馈、已看过滤、冷启动、探索配额、目录耗尽、多样性、模型学习、AUC 打平和 NDCG 已知结果。

## 与公开资料的关系

- [TikTok 官方推荐说明](https://support.tiktok.com/en/using-tiktok/exploring-videos/how-tiktok-recommends-content)：列出了点赞、完整观看、跳过等用户反馈。用于理解行为信号。TikTok 的公开说明不能证明抖音使用完全相同的实现。
- [Covington et al., 2016 · Deep Neural Networks for YouTube Recommendations](https://research.google/pubs/deep-neural-networks-for-youtube-recommendations/)：公开介绍候选生成与排序的两阶段结构。本项目仅借用阶段划分，未复现论文的神经网络。
- [Liu et al., 2022 · Monolith](https://arxiv.org/abs/2209.07663)：讨论面向在线训练的推荐系统和无碰撞 embedding 表。本项目没有实现 Monolith，也没有在线重训全局模型。

这版省去了视频内容理解、embedding 召回、序列模型、分布式训练、多目标长期价值和生产服务。完成练习后，可以按 [`LEARNING.md`](LEARNING.md) 逐步扩展。
